GIT 团队协作

第一步：建立本地个人分支（基于最新的远程代码）

由于团队可能在你本地 dev_V1.0 之后推送了新代码，不要直接基于当前的旧代码建分支，先拉取最新代码。

第二步：日常开发与提交（个人分支操作）

第三步：与团队主分支保持同步（最关键的操作）

团队其他人会往 dev_V1.0 合并代码，你需要频繁把他们的更新同步到你的个人分支，避免最后合并时产生大量冲突。

推荐方案（使用 Rebase，保持提交历史线性整洁）：

如果遇到冲突：

  • 解决冲突文件。
  • git add .
  • git rebase --continue

如果你不想用 Rebase（觉得麻烦），也可以用 Merge（合并）：

建议：每天开始工作前，或者准备提测前，务必执行一次上述同步操作。

第四步：功能开发完毕，合并回团队分支

当你个人分支的功能开发完成并自测通过后，需要合并回团队的 dev_V1.0。

标准做法：

  1. 在 GitLab/GitHub/Gitee 等平台上发起 Merge Request (MR) 或 Pull Request (PR)，请求将 feature/your-name 合并到 dev_V1.0。
  2. 让团队成员进行 Code Review，通过后由负责人点击合并。
